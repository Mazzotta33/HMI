# HMI — копирование в указанный каталог

Лабораторная работа № 2 по дисциплине «Проектирование человеко-машинного интерфейса».
Одна задача реализована в двух парадигмах: **командный язык** и **меню**.
Вариант операции: **копирование в указанный каталог**.

## Запуск

Нужен Python 3.10 или новее с Tkinter (в стандартном установщике Python для Windows
включён по умолчанию). Сторонних зависимостей нет. Выполняйте команды из папки проекта:

```powershell
python make_demo.py
python shell.py demo/Исходные
python menu.py demo/Исходные
```

Можно запускать без аргумента: тогда исходным станет текущий каталог.
В Linux для GUI может потребоваться системный пакет `python3-tk`.

## Возможности

- Список объектов текущего каталога с размерами и датами изменения.
- Переход по относительному или абсолютному пути, переход на уровень выше.
- Копирование одного файла, группы по маске, произвольно выделенных файлов в GUI.
- Маски `*` (любое число символов) и `?` (ровно один), без учёта регистра.
- Пути и имена с пробелами и кириллицей.
- Проверка всех имён назначения перед началом копирования.
- Запрет перезаписи существующих файлов и копирования в исходную папку.
- Справка и понятные сообщения об ошибках.

Копируются обычные файлы текущего каталога, **без рекурсивного обхода папок и без
символических ссылок**. Имена и содержимое сохраняются, исходные файлы остаются
на месте. Метаданные (времена, ACL и альтернативные потоки NTFS) не переносятся.
Каталог назначения должен уже существовать.

## Командный язык

```text
<строка> ::= <команда> { <пробел> <параметр> }
<команда> ::= dir | cd | copy | help | exit
<параметр> ::= <слово> | "<текст с пробелами>"
```

Обратный слеш сохраняется буквально; экранирование внутри кавычек не применяется.
Имена команд и маски нечувствительны к регистру. Разрешение путей `cd` зависит от
файловой системы ОС. Имя/маска источника задаётся без пути: исходные файлы всегда
находятся в текущем каталоге. Каталог назначения — абсолютный путь либо путь
относительно текущего каталога программы.

| Команда | Назначение |
|---|---|
| `dir [маска]` | Просмотреть содержимое каталога |
| `cd [путь]` | Перейти в каталог; без параметра показать путь |
| `copy <имя или маска> <каталог>` | Скопировать файлы |
| `help [команда]` | Показать общую справку или справку по выбранной команде |
| `exit` | Выйти |

Пример после запуска в `demo/Исходные`:

```text
dir
dir *.txt
copy readme.txt ../Результат
copy *.csv ../Результат
cd Фото
cd ..
help copy
exit
```

После первого копирования `readme.txt` повторное копирование этого файла в тот же
каталог завершится сообщением о конфликте, сохранив существующий файл.

## Интерфейс с меню

1. Откройте папку через «Файл → Открыть каталог…» или адресную строку.
2. Выделите один или несколько файлов (Ctrl/Shift). Можно использовать
   «Правка → Выделить все файлы» или «Выделить по маске…».
3. Выберите «Правка → Копировать в…» либо соответствующую кнопку/контекстное меню.
4. Выберите папку назначения, проверьте список файлов и подтвердите копирование.

Фильтр ограничивает отображаемые объекты и область выделения. Двойной щелчок по
папке открывает её, по файлу — начинает выбор назначения. Backspace возвращает
на уровень выше, F5 обновляет список, F1 открывает справку. Заголовки столбцов
меняют сортировку; папки всегда первыми. Меню включает каскадное подменю сортировки
с переключателями. Команда копирования недоступна без выбранных файлов.

Копирование выполняется в рабочем потоке, окно показывает число завершённых файлов.
До окончания операции переходы, новое копирование и закрытие окна блокируются.
Один большой файл может копироваться некоторое время без изменения счётчика.

## Ошибки и целостность

При заранее обнаруженном конфликте, отсутствии файла или неверном назначении
копирование не начинается. Файлы назначения открываются в режиме исключительного
создания: если файл появился после проверки, он также не будет перезаписан.
Если во время операции произошёл сбой, незавершённая копия текущего файла удаляется,
а завершённые копии сохраняются; сообщение содержит их количество.
Группа файлов не является транзакцией. При аварийном завершении процесса или
отключении питания незавершённая копия может остаться на диске.

## Устройство программы и проверка

| Файл | Назначение |
|---|---|
| `fileops.py` | Просмотр, пути, маски, проверка плана и копирование |
| `shell.py` | Разбор команд и консольный цикл |
| `menu.py` | Меню Tkinter, список ttk.Treeview, диалоги, рабочий поток |
| `make_demo.py` | Подготовка воспроизводимого примера без замены существующих файлов |
| `tests/test_hmi.py` | Проверки копирования, ошибок, команд и сохранности данных |
| `tests/test_gui.py` | Проверки состояния меню и фонового копирования |

```powershell
python -m unittest discover -s tests -v
```

GitHub Actions запускает эти проверки на Windows и Linux. Проверки GUI
пропускаются, если в среде нет графического дисплея.

Основные функции общего модуля: `resolve_directory` проверяет путь,
`list_directory` возвращает сведения `DirectoryEntry`, `matches_mask` сравнивает
имя с маской, `select_file_names` отбирает файлы, `build_copy_plan` проверяет
будущие копии, `copy_files` выполняет копирование. Обработчики команд `Shell`
отделены от разбора строки; методы `App` разделяют создание виджетов, диалог
подтверждения и запуск фоновой операции. Рабочий поток передаёт сообщения через
очередь, а обновление виджетов выполняется в главном потоке Tkinter.

Для сравнения парадигм в отчёте можно использовать одни и те же задачи:
копирование одного файла, всех `.txt`, произвольных двух файлов, переход между
папками и просмотр файлов по маске. Время разработки и пользовательских действий
следует измерить на этой реализации; показатели другого варианта не переносятся.
